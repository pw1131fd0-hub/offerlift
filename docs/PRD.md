# OfferLift PRD — 求職者薪資談判智囊

## 1. 產品願景

OfferLift 是一款專為台灣科技業求職者設計的薪資談判輔助工具。透過輸入 Offer 詳情，使用者可獲得客觀的市場評估分數、具體的談判腳本、以及參考薪資區間，從而掌握談判主動權，爭取應得報酬。不同於一般薪資情報站，OfferLift 強調「純前端、數據不上雲」的隱私保護理念，所有計算與數據皆在本地瀏覽器完成。

---

## 2. User Story

### US-01：求職者評估 Offer 價值
**身份**：正在面試科技公司最後一關的求職者
**我希望**：輸入我的 Offer 詳細結構（底薪、獎金、股票、城市、年資）
**以便**：獲得一個客觀的評估分數（0-100）和針對該分數的談判建議

**接受標準**：
- 輸入必要欄位後點擊評估，3 秒內顯示結果
- 評估分數以視覺化環圈呈現，並附上各項加分/減分原因
- 根據分數給出「果斷接受」「可以談判」「必須談判」三種行動建議

---

### US-02：求職者取得談判腳本
**身份**：對談判話術沒有把握的初次轉職者
**我希望**：瀏覽並複製針對不同情境的談判對話腳本
**以便**：在與 HR 電話中能從容應對，不失專業形象

**接受標準**：
- 頁面載明 5 種常見情境（開場、報價低於預期、談判空間、非薪資福利、暫緩決策）
- 每個腳本皆為可直接使用的對話範文，並附上談判要點提示
- 支援一鍵複製到剪貼簿

---

### US-03：求職者查詢市場薪資區間
**身份**：需要市場數據支撐談判立場的轉職者
**我希望**：查詢特定職稱與地區的市場薪資區間
**以便**：在談判時能引用具體數據而非主觀感受

**接受標準**：
- 顯示至少 10 個常見科技職位的年薪區間（min-max，單位：萬 TWD）
- 資料來源註明（104、LinkedIn、CakeResume）
- 用戶可貢獻自己的匿名薪資數據擴充資料庫

## 3. 功能分級

### P0（核心必備，MVP 上線基準）

| 功能 | 描述 | 驗收條件 |
|------|------|----------|
| Offer 評估器 | 輸入薪資結構，輸出 0-100 評估分數與談判建議 | 評估結果在 3 秒內生成；分數計算邏輯公開可查 |
| 談判腳本庫 | 5 種情境的複製可用腳本 | 每個腳本可展開/收合；支援一鍵複製 |
| 薪資參考數據 | 12 個科技職位的市場薪資區間 | 顯示職稱、年薪區間、等級、城市 |
| 城市/年資篩選 | 依據求職者背景調整評估與推薦 | 評估時可選城市（新竹/台北/台中/高雄/遠端）和年資區間 |

### P1（上線後第一個迭代）

| 功能 | 描述 | 預期效益 |
|------|------|----------|
| 深色模式 | 支援系統級深色/淺色切換 | 提升夜間使用者體驗 |
| 談判腳本搜尋 | 依情境關鍵字搜尋腳本 | 快速找到適用腳本 |
| 用戶數據貢獻 | 匿名提交薪資數據至本地端 | 逐步豐富薪資資料庫 |
| 評估歷史記錄 | localStorage 儲存最近 5 次評估 | 方便用戶來回比較 Offer |

### P2（中期規劃，功能增強）

| 功能 | 描述 | 技術考量 |
|------|------|----------|
| Equity/Vesting 分析 | 輸入股票或選擇權明細與 Vesting 排程 | 需解析四年 Vesting + 一年 cliff 結構 |
| 離線可用 (PWA) | 支援 Service Worker 離線快取 | 需manifest.json與快取策略 |
| 多語言支援 | 英文/日文/繁體中文介面 | i18n 框架（待選型） |
| 匯出評估報告 | 將 Offer 評估結果匯出為 PDF | 前端 PDF 生成庫 |

## 4. 非功能需求

### 效能
- 頁面首次載入時間（Largest Contentful Paint）需低於 2.5 秒（在 3G 網路環境下量測）
- Offer 評估計算需在 100ms 內完成（純 JS 本地計算，無網路請求）
- 薪資參考數據表渲染時間需低於 200ms

### 可用性
- 支援響應式設計，桌面與手機（320px 以上）皆可正常操作
- 符合 WCAG 2.1 AA 等級的顏色對比度要求
- 所有交互元素（按鈕、輸入框、下拉選單）皆需可鍵盤操作

### 擴展性
- 薪資數據結構支援未來擴充新職稱、新城市、新貨幣
- 談判腳本以結構化 JSON 存放，方便內容團隊更新（不需改 code）
- 評估演算法模組化，支援未來調整權重或新增維度

### 安全性
- 不向任何外部 API 傳送用戶輸入的薪資數據（純本地計算）
- 用戶貢獻的數據僅存於 localStorage，不上傳至任何伺服器
- 輸入框內容需做基本 XSS 過濾（避免存入惡意 script）
- 禁止在程式碼中 hardcode 任何真實用戶識別資訊

## 5. 技術選型

### 前端框架
- **選擇**：純 HTML + Tailwind CSS（CDN）+ Vanilla JavaScript
- **理由**：MVP 階段極速交付；無需建構流程；CDN 載入 Tailwind 足以應對 Styling 需求；Vanilla JS 避免框架學習曲力，程式碼可直接被未來接手工程師閱讀維護

### 資料儲存
- **選擇**：localStorage
- **理由**：用戶隱私優先，數據不上雲；MVP 不需後端；localStorage 足以應付小量結構化資料（評估歷史、貢獻數據）

### 外部依賴
- **Tailwind CSS**：CDN 版（`cdn.tailwindcss.com`），用於快速建構 UI 元件
- **Google Fonts**：Inter 字體，用於全站字體統一
- **無需其他第三方函式庫**

### 部署方式
- **選擇**：靜態網頁部署至 GitHub Pages
- **理由**：零成本；與 GitHub 原生整合；支援自訂網域；CI/CD 流程可直接用 GitHub Actions 推送後自動部署

### 程式碼品質工具
- **ESLint**：前端程式碼 linting（可選，生產環境非必須）
- **Prettier**：代碼格式化（可選）

## 6. UI/UX 色彩計劃

### 主色彩系統

| 角色 | 色票名稱 | Hex 值 | 使用場景 |
|------|----------|--------|----------|
| Primary | brand-500 | `#22c55e` | 主要 CTA 按鈕、強調色、活躍狀態 |
| Primary Dark | brand-600 | `#16a34a` | Hover 狀態、深色背景上的品牌元素 |
| Primary Deep | brand-900 | `#166534` | 深色對比區塊（如 Hero gradient 終點） |
| Success | green | `#22c55e` | 評估分數高（>= 80）、正面指標 |
| Warning | yellow | `#eab308` | 評估分數中（60-79）、需要注意 |
| Danger | red | `#ef4444` | 評估分數低（< 40）、明顯低於市場警示 |
| Neutral Dark | gray-900 | `#111827` | 主要文字、深色區塊（Footer、談判腳本區） |
| Neutral Mid | gray-100 | `#f3f4f6` | 卡片邊框、分割線、淺色背景 |
| Surface | white | `#ffffff` | 卡片、輸入框、表單背景 |

### 字體規範
- **主要字體**：Inter（Google Fonts）
  - Sans-serif fallback：`system-ui, -apple-system, sans-serif`
- **字重使用**：
  - 400（Regular）：正文、說明文字
  - 500（Medium）：標籤、輔助文字
  - 600（Semibold）：標題、分類標題
  - 700-800（Bold/Extrabold）：Hero 大標、數字分數

### 佈局原則
- **最大內容寬度**：`max-w-5xl`（約 1024px），置中對齊
- **響應式斷點**：
  - Mobile：< 768px（預設）
  - Desktop：>= 768px（`md:` 修飾符）
- **區塊間距**：各 section 以 `py-20 px-6` 達成一致垂直間距
- **卡片圓角**：`rounded-xl`（12px）作為標準卡片圓角
- **陰影系統**：
  - 卡片：`shadow-xl`
  - Hover 浮起：`shadow-lg` + `translateY(-4px)` + `transition: all 0.3s ease`

## 7. 成功指標

### KPI 1：用戶使用深度
- **指標名稱**：單次工作階段平均評估次數
- **目標值**：>= 2.5 次/工作階段
- **量測方式**：Google Analytics 事件追蹤（`evaluate_offer` 事件，在每次點擊「評估我的 Offer」時觸發）
- **意義**：反映用戶是否願意用 OfferLift 比較多個 Offer；次數越高代表工具黏著度越好

### KPI 2：用戶參與度（薪資數據貢獻率）
- **指標名稱**：貢獻按鈕點擊率（Click-through Rate）
- **目標值**：>= 3% 的評估使用者會點擊「貢獻你的薪資數據」
- **量測方式**：Analytics 事件追蹤（`contribute_click`）
- **意義**：用戶願意回饋數據代表產品信任度建立，也是資料庫持續成長的關鍵

### KPI 3：頁面效能
- **指標名稱**：Largest Contentful Paint（LCP）
- **目標值**：< 2.5 秒（Good，等同於 Core Web Vitals Pass）
- **量測方式**：Web Vitals JS 函式庫回傳至 Analytics
- **意義**：免費工具使用者耐心低，效能不佳會直接流失

### KPI 4：用戶回流意願
- **指標名稱**：回訪率（Return Visit Rate，30 天內）
- **目標值**：>= 15%
- **量測方式**：Google Analytics Client ID 跨工作階段追蹤
- **意義**：純工具類產品容易用完即走，回訪率高代表產品有長期價值
