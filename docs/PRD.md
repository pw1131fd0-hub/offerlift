# OfferLift PRD — 求職者薪資談判智囊

## 1. 產品願景

OfferLift 是一款專為台灣科技業求職者設計的薪資談判輔助工具。透過輸入 Offer 詳情，使用者可獲得客觀的市場評估分數、具體的談判腳本、以及參考薪資區間，從而掌握談判主動權，爭取應得報酬。不同於一般薪資情報站，OfferLift 強調數據真實性與即時性，透過後端資料庫整合 104、LinkedIn、CakeResume 等薪資情報，並支援用戶匿名貢獻數據，打造最貼近市場行情的薪資談判平台。

## 2. User Story

### US-01：求職者評估 Offer 價值
**身份**：正在面試科技公司最後一關的求職者
**我希望**：輸入我的 Offer 詳細結構（底薪、獎金、股票、城市、年資）
**以便**：獲得一個客觀的評估分數（0-100）和針對該分數的談判建議

**接受標準**：
- 輸入必要欄位後點擊評估，3 秒內顯示結果
- 評估分數以視覺化環圈呈現，並附上各項加分/減分原因
- 根據分數給出「果斷接受」「可以談判」「必須談判」三種行動建議

### US-02：求職者取得談判腳本
**身份**：對談判話術沒有把握的初次轉職者
**我希望**：瀏覽並複製針對不同情境的談判對話腳本
**以便**：在與 HR 電話中能從容應對，不失專業形象

**接受標準**：
- 頁面載明 5 種常見情境（開場、報價低於預期、談判空間、非薪資福利、暫緩決策）
- 每個腳本皆為可直接使用的對話範文，並附上談判要點提示
- 支援一鍵複製到剪貼簿

### US-03：求職者查詢市場薪資區間
**身份**：需要市場數據支撐談判立場的轉職者
**我希望**：查詢特定職稱與地區的市場薪資區間
**以便**：在談判時能引用具體數據而非主觀感受

**接受標準**：
- 顯示至少 12 個常見科技職位的年薪區間（min-max，單位：TWD）
- 資料來源註明（104、LinkedIn、CakeResume）
- 用戶可貢獻自己的匿名薪資數據擴充資料庫

### US-04：求職者參與薪資論壇討論
**身份**：希望深入了解薪資行情與談判策略的轉職者
**我希望**：在匿名的薪資論壇中瀏覽、搜尋、發表討論
**以便**：從他人的經驗中學習，不暴露個人身份

**接受標準**：
- 用戶可發表匿名討論（職位、城市、薪資範圍、談判經歷）
- 討論串可依公司、職位、城市篩選
- 所有資料存於 PostgreSQL 資料庫
- 禁止任何可識別個人身份的資訊（姓名、電話、email）

### US-05：求職者設定 Offer 截止提醒
**身份**：同時面試多家公司的求職者
**我希望**：追蹤多個 Offer 的截止日期並收到提醒
**以便**：在期限內做出最佳決策

**接受標準**：
- 可新增多個 Offer 追蹤（公司名、職位、截止日期、狀態）
- 支援設定瀏覽器通知提醒
- 可視化時間軸顯示各 Offer 的時間線
- 狀態管理：候選中、談判中、已接受、已拒絕、已過期

### US-06：求職者追蹤面試進度
**身份**：同時面試多家公司的求職者
**我希望**：追蹤各公司的面試階段與進度
**以便**：了解自己在那個環節，掌握整體求職進度

**接受標準**：
- 可新增多個面試追蹤（公司名、職位、當前階段、日期、備註）
- 面試階段：履歷投遞 → HR 電話 → 技術面試 → 主管面試 → 最終面試 → Offer/拒絕
- 可推進面試階段或標記為拒絕

### US-07：求職者設定期望薪資
**身份**：準備開始求職的轉職者
**我希望**：根據我的背景與市場數據，設定合理的期望薪資
**以便**：在求職時有明確的目標，不低估自己

**接受標準**：
- 輸入職位、城市、年資
- 根據市場數據計算三個數字：最低可接受（25th percentile）、市場中等（50th）、目標薪資（75th）
- 可一鍵複製期望薪資敘述用於求職

### US-08：求職者計算稅務
**身份**：需要了解實際税後收入的求職者
**我希望**：輸入我的薪資結構，計算應納所得稅與實際税後收入
**以便**：在談判時能清楚知道自己的實際購買力，並合法節稅

**接受標準**：
- 輸入年薪、年終獎金，可選擇標準或列舉扣除額
- 根據台灣綜所稅制計算應納稅額
- 顯示月薪總計與月薪實領
- 提供獎金分次發放的節稅建議

## 3. 功能分級

### P0（核心必備，MVP 上線基準）

| 功能 | 描述 | 驗收條件 |
|------|------|----------|
| Offer 評估器 | 輸入薪資結構，輸出 0-100 評估分數與談判建議 | 評估結果在 3 秒內生成；分數計算邏輯公開可查 |
| 談判腳本庫 | 5 種情境的複製可用腳本 | 每個腳本可展開/收合；支援一鍵複製 |
| 薪資參考數據 | 12 個科技職位的市場薪資區間 | 顯示職稱、年薪區間、等級、城市 |
| 城市/年資篩選 | 依據求職者背景調整評估與推薦 | 評估時可選城市（新竹/台北/台中/高雄/遠端）和年資區間 |

### P1（上線後第一個迭代）

| 功能 | 描述 | 預期效益 |
|------|------|----------|
| 深色模式 | 支援系統級深色/淺色切換 | 提升夜間使用者體驗 |
| 談判腳本搜尋 | 依情境關鍵字搜尋腳本 | 快速找到適用腳本 |
| 用戶數據貢獻 | 匿名提交薪資數據至後端資料庫 | 逐步豐富薪資資料庫 |
| 評估歷史記錄 | 資料庫儲存最近 10 次評估 | 方便用戶來回比較 Offer |

### P2（中期規劃，功能增強）

| 功能 | 描述 | 技術考量 |
|------|------|----------|
| Equity/Vesting 分析 | 輸入股票或選擇權明細與 Vesting 排程 | 需解析四年 Vesting + 一年 cliff 結構 |
| 離線可用 (PWA) | 支援 Service Worker 離線快取 | manifest.json + sw.js 快取策略 |
| 多語言支援 | 英文/日文/繁體中文介面 | i18n 框架 inline 實作 |
| 匯出評估報告 | 將 Offer 評估結果匯出為 PDF | jsPDF CDN 動態載入 |
| 個人化市場報告 | 根據職位/城市/年資生成專業薪資報告 PDF | 包含市場數據、談判建議、市場趨勢 |

### P3（功能增強）

| 功能 | 描述 | 預期效益 |
|------|------|----------|
| Offer 比較器 | 支援多個 Offer 並排比較，支援雷達圖多維度視覺化 | 幫助用戶在多個 Offer 間做出最佳選擇 |
| 福利計算機 | 計算完整薪酬包價值（年假、餐補、交通補助等） | 將非薪資福利納入總薪酬評估 |
| 薪資成長模擬器 | 根據年資與產業趨勢模擬未來薪資成長 | 幫助用戶規劃職涯發展與談判策略 |
| 談判郵件產生器 | AI 生成專業談判郵件（還價/接受/詢問） | 省去用戶自己撰寫郵件的時間 |
| 薪資數據論壇（匿名） | 讓用戶參與完整的薪資討論區 | 建立社群支持 |
| Offer 截止日期提醒 | 追蹤多個 Offer 的截止日期，支援瀏覽器通知 | 避免錯失理想 Offer |
| 面試進度追蹤器 | 追蹤求職者在各公司的面試進度 | 掌握面試進度 |

## 4. 非功能需求

### 效能
- API 回應時間 < 200ms（95th percentile）
- 頁面首次載入時間（Largest Contentful Paint）需低於 2.5 秒
- Offer 評估計算需在 100ms 內完成

### 可用性
- 支援響應式設計，桌面與手機（320px 以上）皆可正常操作
- 符合 WCAG 2.1 AA 等級的顏色對比度要求
- 所有交互元素皆需可鍵盤操作

### 擴展性
- 薪資資料庫支援未來擴充新職稱、新城市、新貨幣
- 談判腳本以資料庫結構化存放，方便內容團隊更新
- 評估演算法模組化，支援未來調整權重或新增維度

### 安全性
- 用戶輸入的薪資數據僅存於資料庫，不對外暴露
- 用戶貢獻的數據完全匿名
- 輸入框內容需做 XSS 過濾
- 禁止在程式碼中 hardcode 任何真實用戶識別資訊
- 所有 API 端點需基本驗證（API Key 或 JWT）

## 5. 技術選型

### 前端框架
- **選擇**：純 HTML + Tailwind CSS（CDN）+ Vanilla JavaScript
- **理由**：MVP 階段極速交付；無需建構流程；CDN 載入 Tailwind 足以應對 Styling 需求；Vanilla JS 避免框架學習曲力

### 後端框架
- **選擇**：Node.js + Express.js
- **理由**：與前端同為 JavaScript，團隊學習成本低；Express 簡潔靈活，適合 MVP 快速開發；龐大生態系，中介軟體豐富

### 資料庫
- **選擇**：PostgreSQL
- **理由**：開源、成熟穩定；支援 JSON 欄位，方便儲存彈性結構資料；強大的查詢最佳化器；豐富的資料型別支援（陣列、範圍型別等）

### 快取
- **選擇**：Redis
- **理由**：記憶體級存取，速度極快；支援多資料結構（String, Hash, Set, Sorted Set）；適合用作工作階段快取、API 回應快取、限流計數器

### 部署方式
- **選擇**：Docker Compose（本地開發）+ 雲端部署（VPS/Cloud Run）
- **理由**：開發與生產環境一致性；快速水平擴展；維運成本低

## 6. API 端點規格

### 6.1 Offer 評估
- `POST /api/evaluate` — 輸入薪資結構，輸出評估分數與談判建議

### 6.2 薪資數據
- `GET /api/salary-data` — 取得 12 個科技職位的市場薪資區間
- `POST /api/contribute` — 匿名提交薪資數據

### 6.3 Offer 追蹤
- `GET /api/offers` — 取得用戶所有 Offer 追蹤
- `POST /api/offers` — 新增 Offer 追蹤
- `PUT /api/offers/:id` — 更新 Offer 追蹤（狀態、截止日期）
- `DELETE /api/offers/:id` — 刪除 Offer 追蹤

### 6.4 面試進度
- `GET /api/interviews` — 取得用戶所有面試進度
- `POST /api/interviews` — 新增面試進度
- `PUT /api/interviews/:id` — 更新面試進度（推進階段）
- `DELETE /api/interviews/:id` — 刪除面試進度

### 6.5 論壇
- `GET /api/forum` — 取得論壇文章列表（支援分頁、篩選）
- `POST /api/forum` — 發表新文章（匿名）
- `DELETE /api/forum/:id` — 刪除文章

### 6.6 計算機
- `GET /api/calculator/tax` — 所得稅計算
- `GET /api/calculator/benefits` — 福利計算

### 6.7 RSS 資料
- `GET /api/rss/104` — 取得 104 薪資情報（Server-side fetch，快取 1 小時）
- `GET /api/rss/cakeresume` — 取得 CakeResume 文章（Server-side fetch，快取 1 小時）

## 8. UI/UX 色彩計劃

### 主色彩系統

| 角色 | 色票名稱 | Hex 值 | 使用場景 |
|------|----------|--------|----------|
| Primary | brand-500 | `#22c55e` | 主要 CTA 按鈕、強調色、活躍狀態 |
| Primary Dark | brand-600 | `#16a34a` | Hover 狀態、深色背景上的品牌元素 |
| Primary Deep | brand-900 | `#166534` | 深色對比區塊（如 Hero gradient 終點） |
| Success | green | `#22c55e` | 評估分數高（>= 80）、正面指標 |
| Warning | yellow | `#eab308` | 評估分數中（60-79）、需要注意 |
| Danger | red | `#ef4444` | 評估分數低（< 40）、明顯低於市場警示 |
| Neutral Dark | gray-900 | `#111827` | 主要文字、深色區塊 |
| Neutral Mid | gray-100 | `#f3f4f6` | 卡片邊框、分割線、淺色背景 |
| Surface | white | `#ffffff` | 卡片、輸入框、表單背景 |

### 字體規範
- **主要字體**：Inter（Google Fonts）
- **字重使用**：400（Regular）、500（Medium）、600（Semibold）、700-800（Bold/Extrabold）

### 佈局原則
- **最大內容寬度**：`max-w-5xl`（約 1024px），置中對齊
- **響應式斷點**：Mobile < 768px，Desktop >= 768px
- **卡片圓角**：`rounded-xl`（12px）
- **陰影系統**：`shadow-xl`（卡片）、`shadow-lg` + `translateY(-4px)`（Hover）

## 9. 成功指標

### KPI 1：用戶使用深度
- **指標名稱**：單次工作階段平均評估次數
- **目標值**：>= 2.5 次/工作階段

### KPI 2：用戶參與度（薪資數據貢獻率）
- **指標名稱**：貢獻按鈕點擊率
- **目標值**：>= 3% 的評估使用者會點擊「貢獻你的薪資數據」

### KPI 3：頁面效能
- **指標名稱**：Largest Contentful Paint（LCP）
- **目標值**：< 2.5 秒

### KPI 4：用戶回流意願
- **指標名稱**：回訪率（30 天內）
- **目標值**：>= 15%
