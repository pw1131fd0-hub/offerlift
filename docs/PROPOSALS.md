## Proposal 1：智能 Offer 比較，雷達圖視覺化 ✅ 已實作

### 提案概述
增強目前的 Offer 比較器，使用 Chart.js 繪製雷達圖，從多維度（年薪、獎金、股票、福利、城市生活成本）比較 Offer。

### 問題動機
目前的 Offer 比較僅顯示年薪，無法全面比較不同維度。例如：A 公司年薪高但在高消費城市，B 公司年薪略低但提供遠端選項與豐厚股票。

### 提議解決方案
1. 輸入多個 Offer 的完整資料（年薪、獎金、股票價值、福利價值、城市生活成本指數）
2. 使用 Chart.js 繪製雷達圖，可視化每個 Offer 在各維度的表現
3. 自動計算「調整後年薪」（扣除生活成本後的實際購買力）

### 預估工作時程
- 前端實作：4-6 小時
- 測試：2 小時

### 優先級
P2（中期規劃）

### 實作狀態
✅ 已實作（2026-04-10）
- `openCompareAdvisedModal()` 新增多維度資料輸入
- Canvas 2D API 實作雷達圖（5 維度：年薪、獎金、股票價值、福利、評分）
- 比較卡片顯示詳細資訊

## Proposal 2：智能談判教練 Chatbot ✅ 已實作

### 提案概述
基於用戶提供的 Offer 與談判目標，生成個人化的談判策略建議。

### 問題動機
用戶需要一個「24/7 可用」的談判顧問，能根據他們的具體情況（公司規模、產業、職級、競爭 Offer）給出定制化建議，而非只能看到通用腳本。

### 提議解決方案
1. 對話式介面：用戶輸入自己的 Offer 詳情與談判目標
2. AI 分析：根據市場數據與用戶歷史，評估談判難度與成功機率
3. 客製化建議：給出「第一步怎麼說」「HR 可能如何回應」「下一步怎麼做」的完整劇本
4. 實戰模擬：讓用戶預先練習各種可能的情境

### 技術考量
- 純前端、無法使用真正的 AI（隱私考量）
- 可考慮使用規則引擎模拟簡單的對話邏輯
- 或整合 LocalAI / Ollama 在設備端運行

### 預估工作時程
- 規則引擎：8-10 小時
- UI/UX：4 小時

### 優先級
P3（長期規劃）

### 實作狀態
✅ 已實作（2026-04-10）
- `coachQuickAsk()` 新增快捷問題按鈕（低於預期/第一次/競爭 Offer/即將到期）

## Proposal 3：薪資數據論壇（匿名）

### 提案概述
讓用戶不只貢獻單一數據點，而是參與完整的薪資討論區，分享工作經驗與談判策略。

### 問題動機
目前用戶只能匿名貢獻「職位+薪資」，無法獲得更深入的社群支持。用戶想知道：拿到某公司 Offer 的人，談判過程經歷了什麼？最終怎麼解決的？

### 提議解決方案
1. 匿名討論區：用戶可發表自己的 Offer 與談判經歷
2. 公司/職位標籤：方便搜尋同公司、同職位的討論
3. 專家點評：邀請業界人士（HR、獵頭）提供建議（可選功能）
4. 隱私優先：嚴禁暴露可識別個人身份的資訊，所有互動完全匿名

### 技術考量
- 若實現需要後端（討論串儲存、評論系統）
- 可考慮使用 localStorage 模擬離線優先的討論區
- 或使用 Firebase/Supabase 等無伺服器方案

### 預估工作時程
- 討論區前端：6-8 小時
- 後端整合（如需要）：取決於技術選擇

### 優先級
P3（長期規劃）

### 實作狀態
✅ 已實作（2026-04-10）
- 匿名討論區：使用者可發表 Offer 與談判經歷（`submitNewPost()`）
- 公司/職位標籤：方便搜尋同公司、同職位的討論
- 分類過濾：Offer 分享、談判經驗、技巧分享

## Proposal 4：行動裝置 App（PWA 增強）

### 提案概述
將 OfferLift 從 Web 升級為完整的 PWA，可安裝至 iOS/Android 主畫面，支援離線使用與推送通知。

### 問題動機
用戶在面試現場可能需要即時查詢參考數據，但網路可能不穩定。目前的 PWA 已支援離線，但缺少「推送通知」功能（提醒用戶談判deadline、Offer 有效期）。

### 提議解決方案
1. 安裝Prompt：在用戶第二次訪問時顯示安裝提示
2. 推送通知：支援設定「Offer 考慮期限提醒」
3. 小工具：iOS/Android 主畫面小工具，顯示最近評估的 Offer 分數
4. 深層連結：從其他網站（如 LinkedIn）分享 Offer 時，自動開啟 OfferLift 評估

### 技術考量
- Service Worker 需支援 Web Push API
- iOS Safari 的 Push Notification 支援度有限，需漸進增強
- 小工具（Widget）需要原生支援或使用 home screen web app

### 預估工作時程
- PWA 安裝提示：2 小時
- Push Notification：4 小時
- 小工具：6-8 小時

### 優先級
P2（中期規劃）

### 實作狀態
✅ 已實作（2026-04-10）

## Proposal 5：離線優先的資料同步

### 提案概述
讓用戶的評估歷史、貢獻數據可在多設備間同步，但依然保持「不上雲」的隱私理念。

### 問題動機
用戶可能在手機、平板、筆電上都使用 OfferLift，但目前資料僅存在單一設備。用戶希望換設備時能繼續使用自己的歷史資料。

### 提議解決方案
1. Export/Import：手動匯出/匯入 JSON 檔案
2. 加密的 localStorage 備份：使用 Web Crypto API 加密資料後，可上傳至用戶自己的雲端儲存（Google Drive/iCloud）
3. QR Code 分享：生成加密的二維碼，其他設備掃描後可匯入資料
4. 隱私優先：所有資料加密後才離開設備，伺服器只儲存加密 blob，無法識別內容

### 技術考量
- Web Crypto API 用於對稱加密
- 可使用 IndexedDB 而非 localStorage（更大的儲存空間）
- QR Code 生成需要載入 qrcode.js

### 預估工作時程
- Export/Import：2 小時
- 加密同步機制：8-10 小時
- QR Code 功能：4 小時

### 優先級
P3（長期規劃）

### 提案概述
讓用戶可追蹤多個 Offer 的狀態與截止日期，支援設定提醒通知，幫助用戶在期限內做出最佳決策。

### 問題動機
用戶可能同時面試多家公司，收到多個 Offer 後需要追蹤各個 Offer 的狀態、截止日期、談判進度。目前 OfferLift 只能評估單一 Offer，無法管理多個 Offer 的生命週期。

### 提議解決方案
1. Offer 追蹤清單：新增/編輯/刪除 Offer 追蹤

3. 截止日期設定：可設定回覆期限，支援瀏覽器通知提醒
4. Offer 並排比較：從追蹤清單中快速比較多個 Offer
5. 視覺化時間軸：顯示各 Offer 的時間線（收到日期、截止日期）

### 技術考量
- 使用 localStorage 儲存追蹤資料
- 使用 Notification API 發送瀏覽器通知（需用戶授權）
- 結合現有的 Offer 比較器與雷達圖功能

### 預估工作時程

## Proposal 10：台灣薪資稅務計算機 ✅ 已實作

### 提案概述
針對台灣所得稅制設計的稅務計算機，幫助用戶了解不同薪資結構下的實際稅負，並提供年終獎金分次發放等合法節稅建議。

### 問題動機
台灣的所得稅制為累進稅率（5%、12%、20%、30%、35٪），不同薪資結構（包含/不包含獎金、股票、分紅）會造成不同的稅負。用戶需要知道「我的 Offer 實際税後年收入是多少」。

### 提議解決方案
1. 輸入年薪結構（月薪、獎金、補助、年終獎金）
2. 計算個人所得稅（包含標準扣除額/列舉扣除額）
3. 顯示税後月薪與年薪
4. 提供獎金分次發放的節稅建議
5. 顯示有效税率 vs 名目税率

### 技術考量
- 台灣綜所稅税率級距：
  - 0-560,000: 5%
  - 560,001-1,260,000: 12%
  - 1,260,001-2,520,000: 20%
  - 2,520,001-4,720,000: 30%
  - 4,720,001+: 35%
- 標準扣除額：134,000（單身）
- 薪資所得特別扣除額：207,000

### 預估工作時程
- 前端實作：3-4 小時
- 測試：1 小時

### 優先級
P3（功能增強）

### 實作狀態
✅ 已實作（2026-04-11）
- `openTaxModal()` / `closeTaxModal()` 開啟/關閉稅務計算機
- `calculateTax()` 根據台灣綜所稅制計算税額
- 顯示：應納稅額、税後年收入、税後月薪、有效税率
- 提供獎金分次發放節稅建議
- 支援 i18n（ZH/EN/JA）
